# EmotionFlow / expenseTracker

Главная корневая документация по репозиторию. Этот файл задуман как основная точка входа: что здесь находится, как это устроено, как запускать проект, какие модули уже работают и какие технические ограничения сейчас есть в кодовой базе.

## Что это за проект

`expenseTracker` - это монорепозиторий приложения для управления личными финансами с упором на:

- учёт расходов и доходов;
- эмоциональную оценку трат;
- финансовые цели и совместные цели;
- бюджеты по категориям;
- AI-чат и аналитические инсайты;
- челленджи и достижения;
- экспорт отчётов;
- простую административную панель.

Внутри проекта смешиваются два продуктовых имени:

- `EmotionFlow` - основное имя продукта в интерфейсе и документах;
- `ExpanceTracker` / `ExpanseTrackerBackend` - имена каталогов фронтенда и бэкенда в репозитории.

## Что уже реализовано

### Пользовательские возможности

- Лендинг `About` с описанием продукта и мультиязычным контентом.
- Регистрация по email с кодом верификации.
- Логин, смена пароля, смена email, смена username, смена валюты, загрузка аватара.
- Лента транзакций с фильтрацией по датам.
- Добавление и редактирование расходов и доходов.
- Фото к транзакциям и целям.
- Эмоциональная оценка расходов (`low`, `medium`, `high`) и аналитика по эмоциям.
- Категории расходов с возможностью переименования, объединения и массового обновления транзакций.
- Бюджеты по категориям с расчётом прогресса и предупреждениями при 80%+ и превышении.
- Личные цели со статусом прогресса.
- Автораспределение части дохода в цели через `autoAllocatePercent`.
- Совместные цели, приглашения, вклады участников, семейный режим.
- Челленджи по накоплению, которые автоматически создаются на основе похожих целей.
- Достижения за цели и победы в челленджах.
- Генерация отчётов в `PDF`, `Excel`, `HTML` и отправка на email.
- AI-чат с Gemini и fallback-парсером, если AI не настроен.
- Админ-панель для просмотра пользователей, блокировки, создания и удаления аккаунтов.

### Инфраструктурные возможности

- Глобальный префикс API: `/api`.
- `Helmet`, `compression`, `Throttler`, глобальный `ValidationPipe`.

### Что важно знать о frontend

- Фронтенд запускается на `http://localhost:8080`, это задано в `ExpanceTracker/vite.config.ts`.
- Авторизация сейчас построена не на JWT, а на сохранении `user_id`, профиля и служебных значений в `localStorage`.
- В интерфейсе есть три языка: `ru`, `en`, `ja`.
- Денежная база хранения на клиенте считается в `USD`, а отображение конвертируется в `USD`, `UZS`, `JPY`, `RUB`.
- В `main.tsx` есть регистрация service worker, но файла `sw.js` в репозитории нет, поэтому полноценный offline/PWA сценарий пока не завершён.

## Backend: модули и зоны ответственности

### `auth`

Отвечает за:

- запрос кода подтверждения email;
- регистрацию после подтверждения email;
- логин;
- запрос сброса пароля и подтверждение кода;
- смену пароля;
- профиль пользователя;
- смену username, email и валюты.

Особенности реализации:

- email верифицируется 6-значным кодом;
- сброс пароля тоже основан на 6-значном коде;
- реальные email отправляются только если SMTP настроен;
- если SMTP не настроен, сервис работает в mock-режиме и пишет события в лог;
- JWT-поля присутствуют в env-шаблоне, но в текущем коде JWT-аутентификация не используется.

### `users` + `admin`

Отвечает за:

- хранение пользователей;
- поиск по email/username;
- админскую статистику;
- блокировку/разблокировку;
- создание и удаление пользователей;
- смену username и пароля из админки.

Важная деталь:

- superadmin-аккаунт bootstrap-ится через переменные окружения `SUPERADMIN_EMAIL` и `SUPERADMIN_PASSWORD`;
- этот аккаунт создаётся/обновляется автоматически при логине и должен быть обязательно изменён перед любым реальным деплоем.

### `chat`

Это самый насыщенный доменный модуль. Он покрывает:

- AI-чат через Gemini;
- fallback-парсинг сообщений без AI;
- CRUD расходов и доходов;
- эмоциональную аналитику;
- категории расходов;
- экспорт отчётов.

Поддерживаемые AI tools:

- `add_expense`
- `add_income`
- `add_goal`
- `update_goal_progress`
- `get_insights`

Что умеет чат:

- распознавать короткие записи вида `курица 100`, `salary 5000`, `save for MacBook 2000`;
- создавать расход/доход/цель;
- обновлять прогресс цели;
- давать инсайты по расходам, категориям и эмоциям;
- переключаться в режим `emotions`, где AI делает только read-only анализ.

### `goals`

Отвечает за:

- личные цели;
- совместные цели;
- приглашения;
- вклады участников;
- вычисление доступного баланса пользователя.

Ключевая формула:

`доступный баланс = сумма доходов - сумма расходов - сумма, уже распределённая по целям`

Особенности:

- цель нельзя пополнить больше доступного баланса;
- цель нельзя пополнить выше `targetAmount`;
- при удалении цели сумма `currentAmount` фактически возвращается в доступный баланс через перерасчёт;
- приглашение в обычную цель при принятии может конвертировать личную цель в совместную;
- неотвеченные приглашения автоматически отклоняются через 3 дня.

### `budgets`

Отвечает за:

- создание лимитов по категориям;
- периоды `weekly`, `monthly`, `yearly`;
- расчёт потраченной суммы за текущий период;
- индикатор превышения лимита.

Особенности:

- бюджет считается только по расходам;
- бюджеты привязаны к категориям расходов;
- backend умеет отправлять email-предупреждение при 80%+ и при превышении бюджета.

### `challenges`

Отвечает за:

- челленджи накоплений;
- подбор участников по похожим целям;
- прогресс участников;
- определение победителя;
- создание следующего уровня челленджа.

Основная логика:

- похожие цели группируются с допуском около 20%;
- если участников мало, модуль может добирать искусственных пользователей;
- когда участник достигает 100% цели челленджа, он становится победителем;
- победителю начисляется достижение;
- после победы может автоматически создаваться `Next Level` challenge с большей целью.

### `achievements`

Отвечает за:

- хранение достижений;
- локализованные title/description;
- статистику по очкам и победам.

Сейчас в коде явно поддержаны достижения:

- первая созданная цель;
- первая завершённая цель;
- первый присоединённый челлендж;
- победа в челлендже.

### `health`

Возвращает:

- статус;
- timestamp;
- окружение;
- uptime;
- использование памяти.

### `pdf`

Преобразует HTML-отчёт в PDF через headless Chrome (Puppeteer).

## Как устроена бизнес-логика

### Деньги и валюты

- Backend хранит суммы как базовые значения в `USD`.
- Frontend конвертирует суммы в выбранную валюту для отображения.
- Поддерживаются `USD`, `UZS`, `JPY`, `RUB`.

### Расходы

- Расход нельзя создать, если сумма больше доступного баланса.
- Категория может быть указана вручную или вычислена из описания.
- При загрузке фото файл сохраняется локально в `uploads/photos`.
- При удалении расхода связанная локальная фотография тоже удаляется.

### Доходы

- Доход может автоматически распределять часть суммы по целям, если у целей задан `autoAllocatePercent`.
- При удалении дохода модуль пытается откатить это автораспределение.

### Recurring-транзакции

В API предусмотрены `once`, `daily`, `weekly`, `monthly`, но автоматическое размножение записей в текущей реализации фактически сделано только для `daily`.

### Бюджеты

- Бюджет считается по текущему календарному периоду.
- При 80%+ использования или превышении бюджет может отправляться email.

### AI

- Если `GEMINI_API_KEY` не настроен или модель недоступна, чат всё равно работает через fallback-парсер.
- AI умеет не только анализировать расходы, но и создавать цель, доход или расход по сообщению пользователя.

## Локальный запуск

### Требования

- Node.js 20+ желательно для совместимости с текущими Docker-образами и зависимостями.
- npm.
- PostgreSQL для рекомендованного сценария разработки.
- Docker Desktop, если хотите поднять Postgres и backend через compose.

### Вариант 1: локальный запуск с PostgreSQL

#### 1. Подготовить backend

Создайте файл `ExpanseTrackerBackend/.env` и задайте минимум:

```env
PORT=3000
HOST=0.0.0.0
NODE_ENV=development

DB_TYPE=postgres
DB_HOST=localhost
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=postgres
DB_NAME=emotionflow

FRONTEND_URL=http://localhost:8080
GEMINI_API_KEY=

EMAIL_HOST=
EMAIL_PORT=
EMAIL_SECURE=false
EMAIL_USER=
EMAIL_PASS=
EMAIL_FROM=
```

Важно:

- текущий frontend в коде реально работает на `8080`, а не на `5173`;
- поэтому `FRONTEND_URL` для локальной разработки лучше сразу поставить в `http://localhost:8080`;
- иначе получите проблемы с CORS и неправильные ссылки в email.

Запуск backend:

```bash
cd ExpanseTrackerBackend
npm install
npm run start:dev
```

После запуска backend доступен по адресу:

`http://localhost:3000/api`

#### 2. Подготовить frontend

Создайте файл `ExpanceTracker/.env`:

```env
VITE_API_URL=http://localhost:3000/api
```

Запуск frontend:

```bash
cd ExpanceTracker
npm install
npm run dev
```

После запуска frontend доступен по адресу:

`http://localhost:8080`

### Вариант 2: Docker для backend + Postgres

В каталоге `ExpanseTrackerBackend/` уже есть `docker-compose.yml`, который поднимает:

- PostgreSQL;
- backend-сервис.

Команда:

```bash
cd ExpanseTrackerBackend
docker compose up --build
```

Что важно перед запуском:

- проверьте `docker-compose.yml` и замените все примерные пароли/секреты на свои;
- compose не поднимает frontend, его нужно запускать отдельно;
- для frontend всё равно нужен `VITE_API_URL=http://localhost:3000/api`.

### Вариант 3: быстрый MVP-запуск на SQLite

Если не хотите поднимать Postgres, backend умеет работать на SQLite по умолчанию:

- не задавайте `DB_TYPE=postgres`;
- или удалите PostgreSQL-настройки из `.env`;
- backend создаст локальный `db.sqlite`.

Это удобно для прототипа, но не рекомендуется как production-режим.

## Миграция данных

В backend есть скрипт:

```bash
npm run migrate:sqlite-to-postgres
```

Он переносит данные из `db.sqlite` в PostgreSQL и ожидает, что:

- `.env` уже указывает на PostgreSQL;
- Postgres-схема уже существует;
- backend хотя бы один раз запускался с `DB_TYPE=postgres`, чтобы TypeORM создал таблицы.

## Загрузка файлов и локальное хранилище

- Фото транзакций и аватаров складываются в `ExpanseTrackerBackend/uploads/photos`.
- Backend раздаёт их статически по пути `/uploads/photos/...`.
- В корневом `.gitignore` папка `uploads/` уже исключена из git.

## Статус качества и готовности

### Что выглядит рабочим уже сейчас

- базовый end-to-end поток "регистрация -> логин -> работа с финансами";
- CRUD по расходам, доходам, целям и бюджетам;
- совместные цели и приглашения;
- AI-чат и fallback без AI;
- отчёты и email-отправка;
- healthcheck;
- admin-панель для локального администрирования.

### Что требует внимания

- JWT-аутентификация пока не внедрена, несмотря на env-поля и клиентские заготовки.
- Frontend и backend передают `userId`/`adminUserId`, поэтому безопасность сейчас слабая для production.
- `TypeORM synchronize: true`, а миграций схемы нет.
- Тестовые скрипты в `package.json` есть, но реальных тестовых файлов в репозитории сейчас не обнаружено.
- `admin/events` возвращает статический список событий, это не настоящий аудит-лог.
- PWA заявлена частично: есть `manifest.json`, но нет `sw.js`.
- Примеры env и compose содержат конкретные значения, которые нельзя оставлять в реальном окружении.

## Критичные технические замечания

1. Порт фронтенда в коде `8080`, а не `5173`.
2. `ExpanseTrackerBackend/env.example.txt` и связанная документация местами всё ещё ориентируются на `5173`.
3. В коде есть жёстко заданный superadmin. Это обязательно нужно убрать или заменить перед публикацией.
4. В текущем состоянии проект больше похож на развитый MVP / pre-production, чем на полностью production-ready систему.

## Рекомендованный порядок знакомства с проектом

Если заходите в проект впервые, лучше идти так:

1. Прочитать этот `README.md`.
2. Открыть `ExpanceTracker/src/App.tsx`, чтобы увидеть пользовательские маршруты.
3. Открыть `ExpanseTrackerBackend/src/app.module.ts`, чтобы увидеть состав backend-модулей.
4. Пройтись по `ExpanceTracker/src/lib/api.ts`, чтобы понять фронтовой контракт API.
5. Из backend в первую очередь посмотреть `auth`, `chat`, `goals`, `budgets`, `challenges`.
